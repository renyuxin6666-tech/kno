# 定期整理个人知识库

[简体中文](automation.md) · [English](automation.en.md) · [返回首页](../README.md)

在能访问知识库输出工作区的本机 Codex 任务里说：

> 每周日 20:00 按我的时区整理这个知识库。先刷新变化，再核对相关原文，保存独立的理解笔记；没有有用变化时保持安静。

安装提示词已包含这一步。再次配置时，先检查已有任务，复用或修改同一个知识库的整理任务。资料目录、输出工作区、频率和时区需要明确；未提供资料目录时由用户选择，不能猜测并扫描整台电脑。

## 设置与运行

通过 Codex 提供的定期任务能力创建实际任务；也可以在桌面应用的 Scheduled / 定期任务界面配置并检查。不要把保存了提示词或设置文件当作任务已经生效。创建后核对名称、运行工作区、频率、时区和启用状态，并在本机做一次刷新与结果检查。

本机任务需要电脑开机、桌面应用运行、目录与权限可用。网页端任务不能直接读取本机文件夹。[OpenAI 定期任务说明](https://learn.chatgpt.com/docs/automations)。仅需自动更新索引时，可以改用 **Enable-Weekly.cmd**，无需模型调用；不要同时启用两份整理任务。

## 可复用的任务提示词

以下提示词通过工作区指引定位知识库，适用于中文、英文以及原有研究库：

```text
使用 Obsidian Knowledge Workspace 的 maintain-knowledge 工作流，整理这个本机个人知识库。

先读当前工作区 AGENTS.md、配置指向的个人近况、覆盖与缺口，以及上次整理记录。按工作区给出的 Python 和配置路径运行 pipeline.py refresh；同一时间只运行这一份刷新程序。

读取 data/maintenance-latest.json，再读取它引用的本次 changes.jsonl。原资料只读；保留个人近况、手写笔记、手动修改的生成页和历史摘录。不要上传或推送私人资料，不改变账号登录，不安装新服务。

有新增或修改时，选读与当前重点有关的来源，检查原文存在性、哈希、版本和提取缺口。说明新资料可以帮助继续哪项工作、具体冲突、局限和待确认的问题。分别记录文件变化、文档陈述、你的推断、作者确认和实际验证。文件日期、计划、草稿和测试样例不能证明工作已完成。

把有依据的理解另存为知识库个人笔记目录下的自动整理 / Upkeep 中一份带日期的新笔记。引用准确来源路径及必要段落或页码；不要覆盖自动变化日志、个人近况或此前笔记。

没有有用变化或需要处理的问题时保持安静；有重要变化、明确冲突、执行失败或需要我作决定时才提醒。无法访问目录或执行刷新时，说明具体失败，不擅自扩大访问范围。不要自动增加第二个定期任务。
```

## 结果怎样留下来

- `data/maintenance-latest.json`：本次执行状态及准确变化记录的位置。
- `data/runs/<run_id>/changes.jsonl`：可核对的来源变化；数量多时，Markdown 日志只列每类前 100 条。
- 个人笔记中的整理日志：管线生成的目录变化说明。
- 独立的 Agent 笔记：核对来源后的理解、冲突和待确认判断。

来源变化与 Agent 理解分别保存，方便回看依据。原资料没有被全部自动交给模型；选读内容遵循对应产品当前数据设置。[隐私说明](privacy.md)。
